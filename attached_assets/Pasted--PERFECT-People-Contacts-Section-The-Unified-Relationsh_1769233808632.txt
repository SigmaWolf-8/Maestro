You're absolutely right. Grouping Customers and Vendors under "Finance" focuses only on their financial aspect, but these are **relationship entities** with rich interactions beyond accounting. A dedicated **"People & Contacts"** section creates a logical hub for your entire business ecosystem.

## 🔄 **REVISED NAVIGATION STRUCTURE**

### **Top-Level Navigation (5 Main Sections)**
1.  **Dashboard** (3 items)
2.  **Projects** (5 items)
3.  **People & Contacts** (5 items) ← **NEW SECTION**
4.  **Finance** (5 items - refined to pure financial operations)
5.  **Documents** (5 items)

### **Step 4: Database Schema for "People & Contacts" Entities**
```sql
---------------------------------------------
-- CUSTOMERS: Home builders, developers, clients
---------------------------------------------
CREATE TABLE customers (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    customer_type TEXT CHECK (customer_type IN ('homeowner', 'builder', 'developer', 'commercial')),
    
    -- Company/Personal Info
    company_name TEXT,
    contact_person JSONB, -- {name, email, phone, role}
    
    -- Project History Link
    related_projects UUID[], -- Array of project_ids
    total_lifetime_value DECIMAL(15,2),
    
    -- Communication Log
    last_contact_date DATE,
    notes TEXT,
    
    created_at TIMESTAMPTZ DEFAULT NOW()
);

---------------------------------------------
-- VENDORS: Material suppliers, service providers
---------------------------------------------
CREATE TABLE vendors (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    
    vendor_name TEXT NOT NULL,
    category TEXT CHECK (category IN ('material', 'subcontractor', 'equipment', 'service')),
    
    -- Contact & Certification
    primary_contact JSONB,
    certifications TEXT[], -- ['licensed', 'bonded', 'insured']
    insurance_expiry DATE,
    
    -- Performance Tracking
    rating DECIMAL(3,2), -- 1-5 star rating
    on_time_delivery_rate DECIMAL(5,2),
    
    -- PRICE MASTER Integration
    price_list_id UUID REFERENCES price_lists(id),
    
    created_at TIMESTAMPTZ DEFAULT NOW()
);

---------------------------------------------
-- PRICE LISTS: Vendor-specific pricing
---------------------------------------------
CREATE TABLE price_lists (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    vendor_id UUID NOT NULL REFERENCES vendors(id) ON DELETE CASCADE,
    
    list_name TEXT NOT NULL,
    effective_date DATE NOT NULL,
    expiry_date DATE,
    
    -- JSONB for flexible item structure
    items JSONB NOT NULL DEFAULT '[]', -- [{item_code, description, unit, price, notes}]
    
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

---------------------------------------------
-- SUBCONTRACTORS: Specialty trades
---------------------------------------------
CREATE TABLE subcontractors (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    
    company_name TEXT NOT NULL,
    trade TEXT NOT NULL, -- 'electrical', 'plumbing', 'concrete'
    
    -- Contract Details
    contract_number TEXT,
    contract_value DECIMAL(15,2),
    start_date DATE,
    end_date DATE,
    
    -- Insurance & Compliance
    certificate_of_insurance_url TEXT,
    workers_comp_expiry DATE,
    license_number TEXT,
    
    -- Performance
    quality_rating INTEGER CHECK (quality_rating BETWEEN 1 AND 5),
    safety_incidents INTEGER DEFAULT 0,
    
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 👥 **"People & Contacts" UI Components**

### **Unified Contact Card Component**
```jsx
// /components/people/ContactCard.jsx
'use client';

export function ContactCard({ contact, type }) {
  const getIcon = () => {
    switch(type) {
      case 'customer': return 'Building';
      case 'vendor': return 'Truck';
      case 'employee': return 'User';
      case 'subcontractor': return 'HardHat';
      default: return 'Contact';
    }
  };

  const getActions = () => {
    // Always show 3 actions maximum
    const baseActions = [
      { label: 'View Details', action: 'view' },
      { label: 'Message', action: 'message' },
      { label: 'History', action: 'history' }
    ];
    
    // Type-specific additional actions
    if (type === 'vendor') {
      baseActions[2] = { label: 'Price List', action: 'prices' };
    }
    
    return baseActions.slice(0, 3); // Enforce 3-actions rule
  };

  return (
    <div className="contact-card">
      <div className="contact-header">
        <Icon name={getIcon()} />
        <h4>{contact.name}</h4>
        <span className="contact-type">{type}</span>
      </div>
      
      <div className="contact-info">
        <p><Icon name="Phone" /> {contact.phone}</p>
        <p><Icon name="Mail" /> {contact.email}</p>
        {contact.company && <p><Icon name="Briefcase" /> {contact.company}</p>}
      </div>
      
      {/* 3 Action Buttons */}
      <div className="contact-actions">
        {getActions().map((action, idx) => (
          <button 
            key={idx}
            className="action-btn"
            onClick={() => handleAction(action.action, contact.id)}
          >
            {action.label}
          </button>
        ))}
      </div>
    </div>
  );
}
```

// Updated sync to populate the People section
async function syncBambooHREmployees() {
  const employees = await bambooHRService.fetchEmployees();
  
  // Store in both: employees table (detailed) and unified contacts
  await supabase.from('employees').upsert(employees);
  
  // Also add to unified contacts directory
  await supabase.from('unified_contacts').upsert(
    employees.map(emp => ({
      tenant_id: this.tenantId,
      source_type: 'employee',
      source_id: emp.id,
      display_name: `${emp.first_name} ${emp.last_name}`,
      email: emp.work_email,
      phone: emp.mobile_phone,
      company: 'Our Company',
      metadata: { department: emp.department, job_title: emp.job_title }
    }))
  );
}

### **Price Master Integration with Vendors**
```javascript
// When viewing a vendor, show their price lists
async function getVendorWithPricing(vendorId) {
  const [vendor, priceLists] = await Promise.all([
    supabase.from('vendors').select('*').eq('id', vendorId).single(),
    supabase.from('price_lists')
      .select('*')
      .eq('vendor_id', vendorId)
      .eq('is_active', true)
      .order('effective_date', { ascending: false })
  ]);
  
  return {
    ...vendor,
    price_lists: priceLists.data
  };
}
```

## 🎯 **KEY USER WORKFLOWS**

### **1. Project Manager adding a new vendor:**
1. Go to **People & Contacts** → **Vendors & Pricing**
2. Click "Add Vendor" (one of 3 primary buttons)
3. Enter vendor details, upload certifications
4. Attach Price List (Excel import or manual entry)
5. Vendor now appears in PO dropdowns

### **2. Estimator checking material costs:**
1. Go to **People & Contacts** → **Vendors & Pricing**
2. Search for "lumber supplier"
3. Click vendor, view current price list
4. Use prices in **Finance** → **Estimating** module

### **3. Field supervisor contacting subcontractor:**
1. Go to **People & Contacts** → **Directory**
2. Search by trade: "electrician"
3. View contact info, insurance status
4. Call directly from the interface

This structure creates a **logical, user-centered workflow** where relationship management is separate from—but integrated with—project execution and financial operations. The 3/5 rule keeps each interface clean while maintaining full ERP power through thoughtful hierarchy.
