1. Strategic Architecture Overview
The Maestro is a multi-tenant, all-industry ERP web application with a split frontend/backend architecture. It replaces legacy tools (including MS Access-based reporting) with AI-native analytics, in-browser Office document editing, and post-quantum security via the PlenumNET/SFK infrastructure.

Key Architectural Decision: PostgreSQL-Native, Supabase-Deferred
Decision: Use Replit's built-in PostgreSQL directly with Drizzle ORM. Defer Supabase migration to post-MVP stabilization.
Rationale:

Supabase IS PostgreSQL — migration is a pg_dump → pg_restore with zero code changes.
Drizzle ORM schemas, migrations, and queries work identically on both.
Row-Level Security policies written now transfer directly.
Eliminates an external dependency during rapid development.
The DATABASE_URL environment variable pattern ensures the switch is a config change, not a code change.

Migration Trigger Criteria (for future evaluation):

Schema is stable (no weekly migration churn)
RLS policies are tested and production-proven
Seed data and test fixtures are finalized
Team needs managed hosting, built-in Realtime, or Supabase Studio tooling

WBS Engine (ltree)
sqlCREATE TABLE wbs_nodes (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  project_id uuid NOT NULL REFERENCES projects(id),
  parent_id uuid REFERENCES wbs_nodes(id),
  path ltree NOT NULL,              -- e.g., '1.2.3.4'
  code text NOT NULL,               -- Display code: '03.02.01'
  title text NOT NULL,
  level smallint GENERATED ALWAYS AS (nlevel(path)) STORED,
  budgeted_cost numeric(15,2) DEFAULT 0,
  actual_cost numeric(15,2) DEFAULT 0,
  planned_start date,
  planned_end date,
  actual_start date,
  actual_end date,
  percent_complete numeric(5,2) DEFAULT 0,
  template_code_id uuid REFERENCES wbs_master_codes(id),
  meta jsonb DEFAULT '{}',
  sort_order integer DEFAULT 0,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

CREATE INDEX idx_wbs_path ON wbs_nodes USING GIST (path);
CREATE INDEX idx_wbs_project ON wbs_nodes (project_id, path);

Key Design Note — SQL Safety
The AI service generates SQL from natural language. Safety rails:

Input validation — harmful patterns (DROP, DELETE, INSERT, UPDATE) rejected at prompt level
Tenant scoping — all generated SQL includes WHERE tenant_id = ? (enforced by service, backed by RLS)
Read-only execution — AI queries execute through a read-only database role
Audit trail — every query logged with prompt, generated SQL, execution time, security mode
Query timeout — 30-second default, configurable per tenant

WOPI Document Editing Flow
1. User clicks "Edit in Word" on a document
2. Frontend requests WOPI action URL from backend
3. Backend generates signed WOPI access token
4. Frontend opens Office Online iframe with WOPI URL
5. Office Online (Microsoft servers) calls YOUR WOPI endpoints:
   - GET  /wopi/files/:id           → CheckFileInfo (metadata)
   - GET  /wopi/files/:id/contents  → GetFile (bytes)
   - POST /wopi/files/:id/contents  → PutFile (save)

6. Your WOPI host proxies to OneDrive via Graph API
7. Kong gateway enforces auth + PlenumNET encryption on all WOPI traffic
