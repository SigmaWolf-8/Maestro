## **PART 12: HIERARCHICAL NAVIGATION & ROLE-BASED ACCESS CONTROL (3/5 CHOICE UX)**

### **12.1 Core Philosophy & Architecture**
**Objective:** Design a navigation and permission system where users are presented with **3 or 5 clear choices at each decision level**, creating a guided, powerful workflow. Access to subsequent choices is dynamically filtered by their role and parent-level permissions.

**Key Principles:**
1.  **Progressive Disclosure:** Users only see what they need to accomplish their next task.
2.  **Role-Driven Menus:** Navigation items are filters based on `tenant_users.role` and explicit permissions.
3.  **Hierarchical Security:** Access to a child menu or action requires permission for its parent.
4.  **Visual Constraint:** UI components are designed to present 1, 3, or 5 primary options as a default pattern.

```sql
---------------------------------------------
CREATE TABLE navigation_items (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    
    -- HIERARCHICAL STRUCTURE
    parent_id UUID REFERENCES navigation_items(id) ON DELETE CASCADE,
    item_order INTEGER NOT NULL DEFAULT 0,
    
    -- ITEM CONTENT
    item_type TEXT NOT NULL CHECK (item_type IN ('menu', 'action', 'divider', 'header')),
    title TEXT NOT NULL,
    icon_name TEXT, -- Lucide React icon identifier
    path TEXT, -- e.g., '/projects', '/reports/financial'
    component TEXT, -- For dynamic loading: 'ProjectList', 'WbsBuilder'
    
    -- VISUAL BEHAVIOR
    ui_slot TEXT CHECK (ui_slot IN ('sidebar', 'topbar', 'dashboard', 'toolbar')),
    max_children_display INTEGER DEFAULT 5 CHECK (max_children_display IN (3, 5)),
    is_collapsible BOOLEAN DEFAULT TRUE,
    
    -- SECURITY ROOT: HIGH-LEVEL VISIBILITY
    min_role_required TEXT DEFAULT 'viewer' CHECK (min_role_required IN ('viewer', 'accountant', 'project_manager', 'admin')),
    
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    
    CONSTRAINT navigation_path_unique UNIQUE (tenant_id, path)
);

-- Index for efficient parent-child queries and ordering
CREATE INDEX idx_nav_items_hierarchy ON navigation_items(tenant_id, parent_id, item_order);
CREATE INDEX idx_nav_items_role ON navigation_items(tenant_id, min_role_required);

---------------------------------------------
-- 2. ROLE_PERMISSIONS: Granular Overrides
---------------------------------------------
-- Extends the base min_role_required with specific grants/denials
CREATE TABLE role_permissions (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    navigation_item_id UUID NOT NULL REFERENCES navigation_items(id) ON DELETE CASCADE,
    user_role TEXT NOT NULL CHECK (user_role IN ('viewer', 'accountant', 'project_manager', 'admin')),
    
    -- GRANULAR PERMISSIONS
    can_view BOOLEAN DEFAULT TRUE,
    can_access BOOLEAN DEFAULT TRUE, -- Can navigate to the path/component
    can_action BOOLEAN DEFAULT FALSE, -- Can perform the primary action (e.g., 'Create')
    
    -- INHERITANCE RULE
    inherit_from_parent BOOLEAN DEFAULT TRUE,
    
    UNIQUE(tenant_id, navigation_item_id, user_role)
);

---------------------------------------------
-- 3. USER_NAVIGATION_STATE: Personalization
---------------------------------------------
CREATE TABLE user_navigation_state (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES tenant_users(id) ON DELETE CASCADE,
    navigation_item_id UUID NOT NULL REFERENCES navigation_items(id) ON DELETE CASCADE,
    
    -- USER PREFERENCES
    is_pinned BOOLEAN DEFAULT FALSE,
    is_collapsed BOOLEAN DEFAULT FALSE,
    last_accessed TIMESTAMPTZ,
    access_count INTEGER DEFAULT 0,
    
    UNIQUE(tenant_id, user_id, navigation_item_id)
);
```

### **12.3 Navigation Service with Role Filtering**
**Objective:** Create `/lib/navigation-service.js` that builds the hierarchical menu for a user, applying the 3/5 rule and role checks.

**Instructions:** "Create this service file."

```javascript
// /lib/navigation-service.js
import { createClient } from './supabase-server';

export class NavigationService {
    constructor(tenantId, userId, userRole) {
        this.tenantId = tenantId;
        this.userId = userId;
        this.userRole = userRole;
        this.supabase = createClient();
        // Role hierarchy for permission inheritance
        this.roleHierarchy = {
            'viewer': 0,
            'accountant': 1,
            'project_manager': 2,
            'admin': 3
        };
    }

    // MAIN METHOD: Get filtered navigation tree for current user
    async getNavigationTree(uiSlot = 'sidebar') {
        // 1. Fetch all possible navigation items for this tenant
        const { data: allItems, error } = await this.supabase
            .from('navigation_items')
            .select('*, role_permissions!left(*)')
            .eq('tenant_id', this.tenantId)
            .eq('ui_slot', uiSlot)
            .order('item_order', { ascending: true });

        if (error) throw new Error(`Failed to fetch navigation: ${error.message}`);

        // 2. Filter items based on role and permissions
        const filteredItems = this.filterItemsByRole(allItems);

        // 3. Apply the 3/5 Choice Rule: Limit children at each level
        const limitedTree = this.applyChoiceConstraint(filteredItems);

        // 4. Build hierarchical tree structure
        return this.buildHierarchy(limitedTree);
    }

    // ROLE-BASED FILTERING LOGIC
    filterItemsByRole(items) {
        return items.filter(item => {
            // Check base role requirement
            const userRoleLevel = this.roleHierarchy[this.userRole];
            const itemRoleLevel = this.roleHierarchy[item.min_role_required];
            
            if (userRoleLevel < itemRoleLevel) {
                return false; // User role insufficient for base requirement
            }

            // Check for explicit permission override
            const explicitPerm = item.role_permissions?.find(p => p.user_role === this.userRole);
            if (explicitPerm) {
                // If inherit_from_parent is false, use explicit setting
                if (!explicitPerm.inherit_from_parent) {
                    return explicitPerm.can_view;
                }
            }

            return true; // Item is visible to user
        });
    }

    // APPLY 3/5 CHOICE CONSTRAINT
    applyChoiceConstraint(items) {
        const itemMap = new Map(items.map(item => [item.id, { ...item, children: [] }]));
        const rootItems = [];

        // First, build the tree structure
        items.forEach(item => {
            const node = itemMap.get(item.id);
            if (item.parent_id && itemMap.has(item.parent_id)) {
                itemMap.get(item.parent_id).children.push(node);
            } else {
                rootItems.push(node);
            }
        });

        // Recursively limit children to max_children_display (3 or 5)
        const limitChildren = (node) => {
            if (!node.children || node.children.length === 0) return;

            // Sort by order, then pin status, then access frequency
            node.children.sort((a, b) => {
                // Pinned items first
                if (a.is_pinned !== b.is_pinned) return a.is_pinned ? -1 : 1;
                // Then by order
                return a.item_order - b.item_order;
            });

            // Apply the limit (default 5, configurable per item)
            const maxDisplay = node.max_children_display || 5;
            if (node.children.length > maxDisplay) {
                // Separate pinned and unpinned
                const pinned = node.children.filter(c => c.is_pinned);
                const unpinned = node.children.filter(c => !c.is_pinned);
                
                // Always show all pinned, limit unpinned
                const unpinnedToShow = Math.max(0, maxDisplay - pinned.length);
                node.children = [
                    ...pinned,
                    ...unpinned.slice(0, unpinnedToShow)
                ];
                
                // Add a "More..." item if there are hidden items
                if (unpinned.length > unpinnedToShow) {
                    node.children.push({
                        id: `more-${node.id}`,
                        title: `${unpinned.length - unpinnedToShow} more...`,
                        item_type: 'action',
                        icon_name: 'ChevronDown',
                        is_more_action: true,
                        hidden_children: unpinned.slice(unpinnedToShow)
                    });
                }
            }

            // Recurse for remaining children
            node.children.forEach(child => {
                if (!child.is_more_action) {
                    limitChildren(child);
                }
            });
        };

        // Start from root
        rootItems.forEach(limitChildren);
        return rootItems;
    }

    // BUILD HIERARCHICAL TREE
    buildHierarchy(filteredItems) {
        // Items are already hierarchical after applyChoiceConstraint
        return filteredItems;
    }

    // CHECK PERMISSION FOR A SPECIFIC ACTION
    async checkPermission(navigationPath, action = 'access') {
        // Find the navigation item
        const { data: item, error } = await this.supabase
            .from('navigation_items')
            .select('*, role_permissions!left(*)')
            .eq('tenant_id', this.tenantId)
            .eq('path', navigationPath)
            .single();

        if (error || !item) return false;

        // Check hierarchical permission: user must have access to all parents
        const hasParentAccess = await this.checkParentPermissions(item.id);
        if (!hasParentAccess) return false;

        // Check role hierarchy
        const userRoleLevel = this.roleHierarchy[this.userRole];
        const itemRoleLevel = this.roleHierarchy[item.min_role_required];
        if (userRoleLevel < itemRoleLevel) return false;

        // Check explicit permission
        const explicitPerm = item.role_permissions?.find(p => p.user_role === this.userRole);
        if (explicitPerm) {
            switch (action) {
                case 'view': return explicitPerm.can_view;
                case 'access': return explicitPerm.can_access;
                case 'action': return explicitPerm.can_action;
                default: return false;
            }
        }

        // Default permission based on role hierarchy
        return true;
    }

    // RECURSIVE PARENT PERMISSION CHECK
    async checkParentPermissions(itemId) {
        const { data: item, error } = await this.supabase
            .from('navigation_items')
            .select('parent_id, min_role_required')
            .eq('id', itemId)
            .single();

        if (error || !item) return true; // No parent = root level permission OK

        // Check current item's base role requirement
        const userRoleLevel = this.roleHierarchy[this.userRole];
        const itemRoleLevel = this.roleHierarchy[item.min_role_required];
        if (userRoleLevel < itemRoleLevel) return false;

        // Recursively check parent
        if (item.parent_id) {
            return await this.checkParentPermissions(item.parent_id);
        }

        return true; // Reached root successfully
    }

    // LOG NAVIGATION ACCESS FOR PERSONALIZATION
    async logAccess(navigationItemId) {
        await this.supabase
            .from('user_navigation_state')
            .upsert({
                tenant_id: this.tenantId,
                user_id: this.userId,
                navigation_item_id: navigationItemId,
                last_accessed: new Date().toISOString(),
                access_count: this.supabase.sql('COALESCE(access_count, 0) + 1')
            }, {
                onConflict: 'tenant_id,user_id,navigation_item_id'
            });
    }
}
```

```jsx
import { useState, useEffect } from 'react';
import { NavigationService } from '@/lib/navigation-service';
import { ChoiceQuintet } from './ChoiceQuintet';

export function NavigationSidebar({ tenantId, userId, userRole }) {

        setNavTree(tree);
        setLoading(false);

                        items={item.children}

            // Single action item
            return (
                <button
                    key={item.id}
                    className={`nav-action ${activePath === item.path ? 'active' : ''}`}
                    onClick={() => handleItemSelect(item)}
                >
                    {item.icon_name && <Icon name={item.icon_name} />}
                    <span>{item.title}</span>
                </button>
            );
        }

        if (item.is_more_action) {

            loadComponent(item.component);
        }
    };

    }

    return (
        <aside className="navigation-sidebar">
            <div className="sidebar-header">
                <h3>Workspace</h3>
            </div>
            <nav className="sidebar-nav">
                {navTree.map(renderNavItem)}
            </nav>
            {/* Fixed bottom section with 3 key actions */}
            <div className="sidebar-footer">
                <ChoiceTrio
                    items={[
                        { id: 'help', title: 'Help', icon_name: 'HelpCircle' },
                        { id: 'settings', title: 'Settings', icon_name: 'Settings' },
                        { id: 'profile', title: 'Profile', icon_name: 'User' }
                    ]}
                    onSelect={handleItemSelect}
                />
            </div>
        </aside>
    );
```

### **How This Achieves Your Vision:**

1. **3/5 Choice Enforcement:** The `max_children_display` column and `applyChoiceConstraint()` method ensure no menu shows more than 5 choices. Trios (3) are handled as a special optimal case.

2. **Progressive Disclosure with Security:** The `checkParentPermissions()` method ensures users cannot access child items without parent permission, creating true hierarchical security.

3. **Role-Based Filtering:** Items are filtered by `min_role_required` and explicit `role_permissions` overrides before the UI even receives them.

4. **Clean, Modern UI:** The `ChoiceTrio` and `ChoiceQuintet` components provide visually distinct, card-based interfaces that work on desktop and mobile.

5. **Personalization:** The `user_navigation_state` table tracks user behavior to potentially reorder choices based on frequency of use.

This system ensures that a `viewer` role might see only **Dashboard** (with 3 choices), while an `admin` sees **Dashboard**, **Projects** (5 choices), **Finance** (3 choices), and **HR** (5 choices) - each level respecting the 3/5 constraint and security hierarchy.
